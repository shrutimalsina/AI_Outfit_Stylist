# Deployment and verification

Use the [README](../README.md) for startup, catalog publication, and database backups. Run `bash scripts/smoke_compose.sh` to test an isolated fixture stack. It exercises PostgreSQL migrations, snapshot publication, and the frontend proxy. Production operators should terminate TLS at the reverse proxy and mount persistent catalog and database storage.

## Performance measurements

With the API serving the same snapshot, run from the repository root:

```sh
.venv/bin/python -m scripts.benchmark "$SNAPSHOT_DIR" /path/to/photo.jpg top \
  data/reports/benchmark.json --hardware "CPU model and memory" \
  --api http://127.0.0.1:8000
```

Omit `--api` to measure inference and ranking without HTTP. The cold measurement includes encoder initialization and first inference using the current model cache. Each warmed measurement discards one warm-up and reports median and p95. Batch throughput measures encoding of already decoded images. Matrix bytes describe the embedding payload; process memory also includes model weights, metadata, and runtime overhead.

## Single-host production release

Prerequisites are Docker Compose, a host with persistent disk, a TLS reverse
proxy, a validated catalog, and a local copy of the pinned CLIP weights. Set
`POSTGRES_PASSWORD` in a protected `.env` file. Use a URL-safe random value
such as one generated by `openssl rand -hex 32`.

1. Copy the processed manifest, snapshot, images and populated Hugging Face
   cache into the corresponding directories under `data/`. Set
   `STYLIST_IMAGE_ROOT` in `.env` if the images use a different path.
2. From the release checkout, run the following commands. Replace the snapshot
   ID with the validated artifact directory name.

   ```sh
   export COMPOSE_FILE=docker-compose.yml:docker-compose.production.yml
   docker compose config --quiet
   docker compose up --build --wait
   docker compose exec -T backend python -m pipeline.publish_catalog \
     /app/data/processed/manifest.json /app/data/embeddings/<snapshot-id>
   docker compose restart backend
   curl --fail --max-time 120 http://127.0.0.1:5173/health/ready
   ```

3. Configure the host TLS proxy to forward to `127.0.0.1:5173`. Set request
   body limits and per-client rate limits at that proxy. The inner Nginx limit
   also applies to the proxy's shared address, so size it for the deployment.
   Verify readiness, a real image upload, and its result images via HTTPS
   before directing users to the service.

The overlay mounts catalog files read-only and loads CLIP offline. The
database and backend have no published ports. To roll back a catalog, retain
the previous snapshot and manifest, republish them, and restart the backend.
Before a software upgrade, save the database with
`bash scripts/backup_database.sh /path/to/backup.sql` and back up the data
directory separately. Keep the previous release checkout available.

Before starting services, follow the [production handoff](production-handoff.md)
to initialize the private environment file. Validate the assembled release
on a machine with the project Python dependencies:

```sh
HF_HOME="$PWD/data/raw/hf-cache" .venv/bin/python -m scripts.release_preflight \
  data/processed/manifest.json "$SNAPSHOT_DIR" data/raw/polyvore_outfits
```
